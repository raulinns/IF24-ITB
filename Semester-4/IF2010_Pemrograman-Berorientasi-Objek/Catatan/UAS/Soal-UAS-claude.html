Soal 1 — Refactoring Sistem Notifikasi Layanan Keuangan

Bobot: 22%
SOLID Java Interface Design Pattern Java Fundamentals

Sebuah perusahaan finansial teknologi (fintech) memiliki layanan notifikasi transaksi bernama TransaksiNotifier. Setiap kali sebuah transaksi selesai diproses, sistem harus menyimpan catatan transaksi ke penyimpanan data dan mengirimkan pemberitahuan kepada pengguna. Awalnya notifikasi hanya dikirim melalui e-mail, namun sistem berkembang hingga kini mendukung SMS, push notification, dan webhook pihak ketiga.

Tim pengembang awal menulis seluruh logika dalam satu kelas untuk memenuhi tenggat waktu. Kode tersebut diberikan di bawah ini.

// FILE: TransaksiNotifier.java
public class TransaksiNotifier {

    private String dbUrl = "jdbc:mysql://prod-server/fintech";  // (L1)

    public void prosesTransaksi(String userId, double jumlah, String tipe) {

        // --- Validasi input ---
        if (jumlah <= 0) {                                         // (L2)
            System.out.println("Jumlah transaksi tidak valid.");
            return;
        }

        // --- Simpan ke database (logika fiktif) ---               // (L3)
        System.out.println("[DB] Menyimpan transaksi " + tipe
            + " sejumlah " + jumlah + " untuk user " + userId
            + " ke " + dbUrl);

        // --- Kirim notifikasi ---                                 // (L4)
        String pesan = "Transaksi " + tipe + " sebesar Rp"
            + jumlah + " telah berhasil.";

        if (tipe.equals("TRANSFER")) {
            System.out.println("[EMAIL] Ke " + userId + "@mail.com: " + pesan);
            System.out.println("[SMS]   Ke +62xxx: " + pesan);

        } else if (tipe.equals("PEMBAYARAN")) {
            System.out.println("[PUSH]  Ke device " + userId + ": " + pesan);

        } else if (tipe.equals("TOPUP")) {
            System.out.println("[EMAIL] Ke " + userId + "@mail.com: " + pesan);
            System.out.println("[WEBHOOK] POST https://partner.api/notify: " + pesan);
        }
        // Jika tipe lain: tidak ada notifikasi sama sekali         // (L5)
    }
}

Konteks Pengembangan ke Depan

Jenis transaksi akan bertambah (misalnya INVESTASI, CICILAN). Kanal notifikasi baru sedang direncanakan (WhatsApp, in-app). Kombinasi tipe transaksi–kanal notifikasi akan berubah secara berkala sesuai keputusan bisnis. Tim QA juga mengeluhkan bahwa kelas ini sangat sulit diuji secara unit.
Tugas Anda
  1. Identifikasi pelanggaran prinsip SOLID. Dari kode TransaksiNotifier di atas, sebutkan minimal tiga prinsip SOLID yang dilanggar. Untuk setiap pelanggaran:
    • Sebutkan nama prinsip dan kepanjangannya.
    • Tunjukkan label baris (L1–L5) atau bagian kode yang menjadi bukti konkret pelanggaran tersebut.
    • Jelaskan secara singkat dampak praktisnya jika kode dibiarkan seperti ini (misalnya: apa yang harus diubah jika kanal notifikasi baru ditambahkan).
    (Jawaban berupa analisis singkat, belum perlu menulis kode.)
  2. Rancang ulang kontrak sistem. Buatlah dua interface berikut yang memisahkan tanggung jawab secara tepat:
    • KanalNotifikasi: merepresentasikan satu kanal pengiriman pesan. Tentukan method yang tepat beserta parameter dan tipe kembaliannya.
    • TransaksiRepository: merepresentasikan operasi penyimpanan satu catatan transaksi. Tentukan method yang tepat.
    Tuliskan deklarasi lengkap kedua interface tersebut, lengkap dengan Javadoc singkat pada setiap method.
  3. Terapkan Design Pattern dan implementasikan class inti.
    1. Sistem baru harus memungkinkan penambahan kanal notifikasi tanpa mengubah kode TransaksiService. Sebutkan satu design pattern yang paling tepat untuk kebutuhan ini dan jelaskan alasannya (satu paragraf singkat).
    2. Implementasikan class EmailNotifikasi dan class SmsNotifikasi sebagai implementasi konkret dari interface KanalNotifikasi. Setiap class cukup mencetak pesan ke konsol dengan format yang menunjukkan kanal dan penerima.
    3. Implementasikan class TransaksiService yang telah direfactor. Class ini harus:
      • Menerima TransaksiRepository dan List<KanalNotifikasi> melalui constructor injection.
      • Memiliki method prosesTransaksi(String userId, double jumlah, String tipe) yang memanggil semua kanal yang telah didaftarkan.
      • Tidak mengandung blok if-else atau switch yang hardcode nama tipe transaksi.
      • Melempar IllegalArgumentException jika jumlah <= 0.
  4. Tulis class MainNotifikasi yang mendemonstrasikan desain baru. Program harus:
    • Membuat implementasi TransaksiRepository anonim atau class dalam (inner class) sederhana yang hanya mencetak konfirmasi penyimpanan.
    • Membuat dua instance kanal notifikasi yang berbeda (EmailNotifikasi dan SmsNotifikasi).
    • Membuat satu instance TransaksiService dengan kanal dan repository di atas.
    • Memproses dua transaksi dengan tipe berbeda dan menampilkan output notifikasinya.
    • Menangkap dan mencetak exception jika transaksi dengan jumlah 0 dicoba.

Soal 2 — Validasi dan Pemrosesan Data Pendaftaran

Bobot: 18%
Java Fundamentals Java–C++ Comparison String Exception Assertion

Sebuah platform kursus daring sedang membangun modul pendaftaran pengguna baru. Seorang developer dengan latar belakang C++ menulis kode Java berikut untuk memvalidasi dan memformat data pendaftaran. Kode ini berhasil dikompilasi (kecuali satu baris yang ditandai), namun mengandung sejumlah masalah semantik, logika, dan kebiasaan C++ yang tidak tepat ketika diterapkan di Java.

// FILE: RegistrasiService.java  (mengandung masalah yang disengaja)
import java.util.ArrayList;
import java.util.List;

public class RegistrasiService {

    // ── Bagian A: Membangun tag HTML dari daftar kursus ───────────────
    public String buatTagKursus(List<String> daftarKursus) {
        String hasil = "";
        for (String kursus : daftarKursus) {
            hasil = hasil + "<li>" + kursus + "</li>";  // baris (A1)
        }
        return "<ul>" + hasil + "</ul>";
    }

    // ── Bagian B: Memeriksa apakah username valid ─────────────────────
    public boolean isUsernameValid(String username) {
        String cleaned = username.trim().toLowerCase();
        String reserved = new String("admin");           // baris (B1)

        if (cleaned == reserved) {                       // baris (B2)
            return false;
        }
        if (cleaned == "superuser" || cleaned == "root") { // baris (B3)
            return false;
        }
        return cleaned.length() >= 4;
    }

    // ── Bagian C: Memformat nama lengkap ──────────────────────────────
    // Setiap kata diawali huruf kapital, sisa huruf kecil.
    // Contoh masukan: "  bUDI   santOSO  " → keluaran: "Budi Santoso"
    public String formatNama(String nama) {
        assert nama != null;
        String[] kata = nama.trim().split("\\s+");
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < kata.length; i++) {
            String k = kata[i];
            sb.append(k.substring(0, 1).toUpperCase());  // baris (C1)
            sb.append(k.substring(1).toLowerCase());     // baris (C2)
            if (i < kata.length - 1) sb.append(" ");
        }
        return sb.toString();
    }

    // ── Bagian D: Mendaftarkan pengguna baru ──────────────────────────
    public void daftarPengguna(String username, String email, String nama) {
        if (!isUsernameValid(username)) {
            throw new Exception("Username tidak valid: " + username); // (D1) ← compile error
        }
        if (email == null || !email.contains("@")) {
            throw new RuntimeException("Format email salah.");
        }
        assert formatNama(nama).length() > 0;           // baris (D2)
        System.out.println("Pengguna terdaftar: "
            + formatNama(nama) + " [" + username + "] <" + email + ">");
    }

    // ── Bagian E & F: Program utama untuk pengujian ──────────────────
    public static void main(String[] args) {
        RegistrasiService svc = new RegistrasiService();

        // Pengujian isUsernameValid
        String u1 = "admin";
        String u2 = new String("admin");
        System.out.println(svc.isUsernameValid(u1));   // baris (E1)
        System.out.println(svc.isUsernameValid(u2));   // baris (E2)

        // Pengujian formatNama
        System.out.println(svc.formatNama("  bUDI   santOSO  ")); // baris (F1)
        System.out.println(svc.formatNama(""));                   // baris (F2)

        // Pengujian daftarPengguna (asumsikan baris D1 sudah diperbaiki)
        try {
            svc.daftarPengguna("admin", "admin@mail.com", "Admin User");
        } catch (Exception e) {
            System.out.println("Tangkap: " + e.getMessage());     // baris (G1)
        }
    }
}
Tugas Anda
  1. Analisis Bagian A — buatTagKursus.
    1. Jelaskan masalah performa pada baris (A1) ketika daftarKursus berisi 1.000 elemen. Kaitkan penjelasan Anda dengan sifat immutability objek String di Java dan apa yang sebenarnya terjadi di memori pada setiap iterasi.
    2. Tuliskan versi perbaikan method buatTagKursus menggunakan kelas yang tepat dari Java Standard Library, dan jelaskan secara singkat mengapa kelas tersebut lebih efisien.
    3. Seorang developer C++ mengatakan: "Di C++ saya bisa meng-overload operator+= pada kelas String buatan saya agar akumulasi string menjadi efisien secara custom." Jelaskan mengapa pendekatan tersebut tidak tersedia di Java, dan sebutkan padanan idiomatik Java-nya.
  2. Analisis Bagian B — isUsernameValid.
    1. Jelaskan mengapa baris (B1) menunjukkan kebiasaan yang tidak idiomatik di Java meskipun tidak menyebabkan compile error maupun hasil yang salah dalam semua kondisi.
    2. Jelaskan mengapa perbandingan pada baris (B2) dan (B3) menghasilkan perilaku yang tidak dapat diprediksi. Kaitkan penjelasan Anda dengan perbedaan antara object identity dan object equality di Java. Kemudian bandingkan dengan perilaku operator == pada std::string di C++ — apakah perbedaan semantiknya sama atau berbeda?
    3. Tuliskan versi perbaikan method isUsernameValid yang benar.
    4. Berdasarkan kode pada Bagian E dengan implementasi yang belum diperbaiki: jelaskan apakah baris (E1) dan (E2) pasti mencetak nilai yang sama. Apa yang menentukan hasilnya? (Petunjuk: perhatikan bagaimana u1 dan u2 dibuat.)
  3. Analisis Bagian C dan D — formatNama dan daftarPengguna.
    1. Baris (C1) berpotensi melempar exception dalam kondisi tertentu. Exception apa yang akan dilempar, dan berikan satu contoh nilai argumen nama yang — setelah melewati baris assert dan split — akan memicu exception tersebut pada (C1). (Petunjuk: pikirkan kasus kata kosong setelah proses split.)
    2. Perbaiki method formatNama agar aman terhadap kondisi tersebut, dan pastikan method mengembalikan "" jika seluruh input setelah trim() adalah string kosong.
    3. Baris (D1) menyebabkan compile error. Jelaskan mengapa demikian, dan tuliskan dua alternatif perbaikan pada deklarasi method daftarPengguna beserta trade-off masing-masing alternatif. Kaitkan jawaban Anda dengan perbedaan antara checked exception dan unchecked exception di Java, serta jelaskan bagaimana konsep ini berbeda dari mekanisme exception di C++ (tidak ada checked/unchecked di C++).
    4. Baris (D2) menggunakan assert untuk memeriksa hasil formatNama. Apakah ini penggunaan assertion yang tepat? Jelaskan perbedaan antara penggunaan assert untuk internal invariant dan penggunaan exception untuk validasi input pengguna, lalu tambahkan satu contoh assert lain yang lebih sesuai di dalam method daftarPengguna.

Soal 3 — Katalog Aset Digital dengan Generic Container

Bobot: 25%
Generics Wildcard Collection Exception Interface

Sebuah platform distribusi konten digital menyimpan tiga jenis aset: Gambar (foto dan ilustrasi), Video (klip dan film pendek), serta Audio (musik dan podcast). Setiap aset memiliki atribut dasar berupa id (String, unik dalam platform), judul (String), dan ukuranMB (double). Selain itu, masing-masing jenis aset memiliki atribut spesifik:

  • Gambar: resolusi (String, format "1920x1080")
  • Video: durasiDetik (int) dan resolusi (String)
  • Audio: durasiDetik (int) dan bitrateKbps (int)

Platform ini membutuhkan sebuah katalog generik yang dapat menyimpan dan mengelola koleksi aset berdasarkan id-nya. Selain itu, sistem membutuhkan dua fungsi utilitas: satu untuk menghitung total ukuran dari daftar aset campuran, dan satu untuk menggabungkan (batch upload) aset dari satu sumber ke dalam sebuah katalog tujuan.

Hierarki Class yang Ditetapkan

AsetDigital adalah abstract class. Gambar, Video, dan Audio adalah subclass konkret dari AsetDigital. Untuk subclass tersebut, Anda cukup menuliskan deklarasi class, konstruktor berparameter, dan override method getInfo(); implementasi lengkap lainnya tidak perlu dituliskan.

Berikut adalah contoh urutan operasi yang harus dapat dilakukan oleh katalog dan exception yang harus dihasilkan pada kondisi tertentu:

Tugas Anda
  1. Implementasikan hierarki class aset.
    • Tuliskan AsetDigital sebagai abstract class dengan atribut id, judul, ukuranMB (semua private), konstruktor berparameter, getter untuk ketiga atribut, deklarasi abstract method String getInfo(), serta override toString() yang mendelegasikan ke getInfo().
    • Tuliskan deklarasi class Gambar, Video, dan Audio: masing-masing cukup memiliki konstruktor berparameter (semua atribut, termasuk yang spesifik) dan override getInfo() yang mengembalikan string deskriptif yang memuat seluruh atribut class tersebut.
  2. Implementasikan dua custom exception.
    • AsetTidakDitemukanException: harus berupa checked exception. Konstruktornya menerima String id dan membentuk pesan error yang informatif.
    • AsetDuplikatException: harus berupa unchecked exception. Konstruktornya menerima String id dan membentuk pesan error yang informatif.
    Setelah implementasi, jelaskan secara singkat (satu kalimat per exception) mengapa Anda memilih checked untuk yang pertama dan unchecked untuk yang kedua, dilihat dari sifat kondisi yang diwakili oleh masing-masing exception.
  3. Implementasikan class Katalog<T extends AsetDigital> dengan ketentuan berikut:
    • Gunakan HashMap<String, T> sebagai penyimpanan internal, dengan kunci berupa id aset.
    • void tambah(T aset): menambahkan aset; melempar AsetDuplikatException jika id sudah ada.
    • T cari(String id) throws AsetTidakDitemukanException: mengembalikan aset bertipe T; melempar exception jika tidak ditemukan.
    • void hapus(String id) throws AsetTidakDitemukanException: menghapus aset; melempar exception jika tidak ditemukan.
    • List<T> semuaAset(): mengembalikan semua aset sebagai list (urutan bebas).
    • double ukuranTotal(): mengembalikan jumlah ukuranMB seluruh aset.
  4. Implementasikan dua static generic method utilitas dalam class bernama KatalogUtils:
    1. Method dengan signature:
      public static double hitungTotalUkuran(List<? extends AsetDigital> daftar)
      yang menjumlahkan ukuranMB dari semua elemen dalam daftar. Setelah implementasi, jelaskan mengapa ? extends AsetDigital lebih tepat digunakan di sini dibandingkan dengan tipe konkret AsetDigital, dan mengapa ? super AsetDigital tidak cocok.
    2. Method dengan signature:
      public static <T extends AsetDigital> void uploadBatch(List<? super T> tujuan, List<T> sumber)
      yang menambahkan semua elemen dari sumber ke dalam tujuan satu per satu. Jelaskan mengapa ? super T digunakan pada parameter tujuan dan bukan ? extends T. (Petunjuk: pikirkan operasi apa yang dilakukan terhadap tujuan di dalam method ini.)
  5. Tulis class MainKatalog yang mendemonstrasikan seluruh fungsionalitas di atas. Anggaplah semua class dari poin (a)–(d) sudah diimplementasikan. Program main harus:
    • Membuat sebuah Katalog<AsetDigital>.
    • Menambahkan minimal satu instance Gambar, satu Video, dan satu Audio.
    • Mencoba menambahkan aset dengan id yang sudah ada, menangkap AsetDuplikatException, dan mencetak pesannya.
    • Mencari aset dengan id yang tidak ada, menangkap AsetTidakDitemukanException, dan mencetak pesannya.
    • Membuat sebuah PriorityQueue<AsetDigital> dengan Comparator yang mengurutkan aset dari ukuranMB terbesar ke terkecil, mengisi antrian dengan semua aset dari katalog, lalu mengosongkan antrian sambil mencetak setiap aset.
    • Memanggil KatalogUtils.hitungTotalUkuran dengan list yang berisi campuran subkelas dan mencetak hasilnya.

Soal 4 — Sistem Reservasi Kursi Konser Berbasis Thread

Bobot: 20%
Multithreading Exception Collection Java Fundamentals

Sebuah platform tiket konser daring memiliki fitur pemesanan kursi (seat reservation). Setiap konser memiliki denah kursi yang direpresentasikan sebagai peta status: tiap kursi memiliki ID unik (contoh: "A1", "B3") dan status apakah sudah dipesan atau belum. Ketika ribuan pengguna mengakses sistem secara bersamaan, banyak thread berlomba memesan kursi yang sama.

Tim developer menulis skeleton berikut sebagai titik awal, namun menyadari implementasinya tidak thread-safe dan meminta Anda memperbaikinya.

// FILE: SistemReservasi.java  (BELUM thread-safe — perlu diperbaiki)
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class SistemReservasi {

    // Status kursi: true = sudah dipesan, false = tersedia
    private Map<String, Boolean> statusKursi = new HashMap<>(); // (K1)
    private int totalPesananBerhasil = 0;                         // (K2)

    public SistemReservasi(List<String> daftarKursi) {
        for (String id : daftarKursi) {
            statusKursi.put(id, false);
        }
    }

    /**
     * Memesan sebuah kursi. Kembalikan true jika berhasil,
     * false jika kursi sudah dipesan oleh orang lain.
     */
    public boolean pesanKursi(String idKursi) {             // (K3)
        Boolean status = statusKursi.get(idKursi);          // (K3a)
        if (status == null) {
            throw new IllegalArgumentException(
                "Kursi tidak dikenal: " + idKursi);
        }
        if (!status) {                                      // (K3b)
            statusKursi.put(idKursi, true);                 // (K3c) ← masalah utama
            totalPesananBerhasil++;                         // (K3d) ← masalah kedua
            return true;
        }
        return false;
    }

    public int getTotalPesananBerhasil() { return totalPesananBerhasil; }

    public long getKursiTersedia() {
        return statusKursi.values().stream().filter(s -> !s).count();
    }
}

// FILE: ThreadPemesan.java
public class ThreadPemesan implements Runnable {
    private final SistemReservasi sistem;
    private final String idKursi;
    private final String namaPemesan;

    public ThreadPemesan(SistemReservasi sistem,
                         String idKursi, String namaPemesan) {
        this.sistem = sistem;
        this.idKursi = idKursi;
        this.namaPemesan = namaPemesan;
    }

    @Override
    public void run() {
        boolean berhasil = sistem.pesanKursi(idKursi);      // (K4)
        if (berhasil) {
            System.out.println("[BERHASIL] " + namaPemesan
                + " memesan kursi " + idKursi);
        } else {
            System.out.println("[GAGAL]    Kursi " + idKursi
                + " sudah dipesan. Pemesan: " + namaPemesan);
        }
    }
}
Tugas Anda
  1. Identifikasi masalah concurrency.
    1. Jelaskan secara konkret satu skenario race condition yang dapat terjadi pada method pesanKursi (area K3b–K3c). Tuliskan urutan langkah eksekusi dua thread (Thread-A dan Thread-B) yang dapat menyebabkan keduanya sama-sama mendapatkan return true untuk kursi yang sama. Gunakan format notasi seperti: Thread-A melakukan (K3b), Thread-B melakukan (K3b), ...
    2. Jelaskan mengapa totalPesananBerhasil++ pada baris (K3d) juga berpotensi menimbulkan data race, meskipun kodenya terlihat sederhana. Jelaskan pula mengapa HashMap pada (K1) tidak aman diakses langsung dari banyak thread secara bersamaan.
  2. Perbaiki SistemReservasi agar thread-safe dengan ketentuan:
    1. Ganti HashMap dengan ConcurrentHashMap pada deklarasi statusKursi.
    2. Ganti int totalPesananBerhasil dengan AtomicInteger. Sesuaikan semua penggunaan field ini di seluruh method.
    3. Pastikan blok cek-dan-set pada area (K3b–K3c) bersifat atomic menggunakan method replace(key, oldValue, newValue) dari ConcurrentHashMap. Tuliskan implementasi method pesanKursi yang telah diperbaiki secara lengkap dan jelaskan secara singkat mengapa replace dengan tiga argumen memberikan jaminan atomicity.
    4. Tambahkan custom checked exception KursiTidakDikenalException untuk menggantikan IllegalArgumentException pada method pesanKursi. Sesuaikan signature method, dan tangani exception ini di dalam method run() milik ThreadPemesan dengan mencetak pesan error yang informatif.
  3. Tulis class MainReservasi yang mendemonstrasikan sistem thread-safe. Anggaplah SistemReservasi dan ThreadPemesan sudah diperbaiki. Program harus:
    • Membuat daftar 5 kursi: "A1", "A2", "A3", "A4", "A5".

Soal 5 — Arsitektur Plugin Laporan Dinamis

Bobot: 15%
Reflection Interface Design Pattern Exception

Sebuah sistem analitik penjualan membutuhkan fitur ekspor laporan ke berbagai format: teks biasa (PlainTextPlugin), CSV (CsvPlugin), dan Markdown (MarkdownPlugin). Format baru dapat ditambahkan di masa depan oleh tim yang berbeda, tanpa mengubah kode inti sistem. Nama class plugin disimpan dalam sebuah file konfigurasi — dalam konteks soal ini, direpresentasikan sebagai List<String> berisi fully-qualified class name.

Sistem harus memuat plugin secara dinamis saat runtime menggunakan Java Reflection. Sistem tidak boleh meng-hardcode nama class plugin dalam logikanya. Seluruh plugin harus mematuhi kontrak yang ditetapkan oleh sebuah interface, dan sistem harus memverifikasi kepatuhan tersebut sebelum menggunakan plugin.

Spesifikasi Interface LaporanPlugin

Interface LaporanPlugin memiliki tepat dua method:
  • String getNamaFormat() — mengembalikan nama format, misalnya "CSV".
  • String ekspor(List<String[]> data, String[] header) — menerima data tabel (setiap elemen String[] adalah satu baris data) dan array nama kolom, lalu mengembalikan String hasil ekspor dalam format plugin tersebut.
