Soal 1. Refactoring Sistem Notifikasi Bantuan Darurat

Bobot: 22%
Materi yang diuji: Prinsip SOLID, Java Interface, Java Fundamentals, Collection, Exception, dan Design Pattern.

Narasi Kasus

Sebuah pusat koordinasi relawan memiliki aplikasi yang menerima laporan kebutuhan bantuan dari posko lapangan. Setiap laporan memiliki nomor laporan, nama lokasi, tingkat urgensi, dan pesan ringkas. Pada versi awal aplikasi, satu kelas melakukan seluruh pekerjaan: memvalidasi laporan, menentukan isi pesan, mencetak pesan ke terminal, serta mengirim pesan menggunakan kanal tertentu.

Saat ini sistem hanya mendukung pengiriman melalui pesan singkat. Dalam waktu dekat, pusat koordinasi ingin menambahkan kanal surel dan aplikasi percakapan. Selain itu, format pesan untuk laporan KRITIS harus dapat berbeda dari laporan biasa tanpa memodifikasi seluruh bagian aplikasi setiap kali ada perubahan aturan.

Desain Awal yang Diberikan

// File: AlertService.java
import java.util.ArrayList;
import java.util.List;

public class AlertService {
    private List<String> sentLogs = new ArrayList<>();

    public void sendAlert(String reportId, String location,
                          String urgency, String message,
                          String channel) {
        if (reportId == null || reportId.isBlank()) {
            throw new IllegalArgumentException("ID laporan kosong");
        }

        String formatted = "[" + urgency + "] " + location + ": " + message;

        if (channel.equals("SMS")) {
            System.out.println("SMS: " + formatted);
        } else if (channel.equals("EMAIL")) {
            System.out.println("EMAIL: " + formatted);
        } else if (channel.equals("CHAT")) {
            System.out.println("CHAT: " + formatted);
        }

        sentLogs.add(reportId + " - " + channel);
    }

    public List<String> getSentLogs() {
        return sentLogs;
    }
}

Spesifikasi Sistem Baru

  1. Sebuah laporan direpresentasikan oleh kelas ReliefReport dengan data: reportId, location, urgency, dan message.
  2. Kanal pengiriman harus dapat ditambahkan tanpa mengubah kelas pengatur proses pengiriman yang sudah stabil.
  3. Format pesan dapat dipilih secara independen dari kanal pengiriman. Minimal tersedia: format pesan ringkas dan format pesan prioritas.
  4. Pengiriman laporan yang sudah berhasil dilakukan dicatat sebagai log dalam suatu collection.
  5. Pengiriman terhadap laporan yang tidak valid harus menghasilkan exception yang sesuai.

Batasan Implementasi

  • Gunakan interface untuk kontrak kanal pengiriman dan kontrak format pesan.
  • Gunakan satu design pattern yang sesuai agar pemilihan cara memformat pesan dapat diganti tanpa mengubah proses pengiriman utama.
  • Implementasi cukup mendukung tiga kanal: SMS, Email, dan Chat.
  • Log tidak boleh dapat diubah secara langsung oleh pemanggil melalui nilai kembalian getter.

Soal 2. Pemrosesan Kode Akses Peserta Workshop

Bobot: 18%
Materi yang diuji: Pengenalan Bahasa Java, Padanan Java–C++, Java String, Exception, dan Assertion.

Narasi Kasus

Panitia sebuah workshop teknologi memberikan kode akses kepada setiap peserta dengan format: NAMA-TAHUN-KATEGORI. Contoh kode valid adalah ENDRA-2026-STUDENT. Nama peserta harus terdiri atas huruf, tahun harus berada pada rentang 2020 sampai 2030, dan kategori hanya boleh bernilai STUDENT, PUBLIC, atau STAFF.

Seorang programmer yang sebelumnya banyak menggunakan C++ menulis implementasi awal berikut. Program dimaksudkan untuk memvalidasi kode, menormalkan tulisan menjadi huruf kapital, dan menghitung jumlah kode valid yang diproses.

Potongan Kode Bermasalah

// File: AccessCodeProcessor.java
public class AccessCodeProcessor {
    private int validCount = 0;

    public boolean isStudentCategory(String category) {
        return category == "STUDENT";
    }

    public String normalize(String rawCode) {
        rawCode.toUpperCase();
        return rawCode;
    }

    public String extractName(String normalizedCode) {
        String[] parts = normalizedCode.split("-");
        assert parts.length == 3 : "Format kode dari pengguna tidak benar";
        return parts[0];
    }

    public void process(String code) {
        String normalized = normalize(code);

        if (normalized.length() == 0) {
            System.out.println("Kode kosong");
            return;
        }

        String[] parts = normalized.split("-");
        int year = Integer.parseInt(parts[1]);

        if (isStudentCategory(parts[2])) {
            System.out.println("Akses mahasiswa: " + parts[0]);
        }

        validCount++;
    }

    public int getValidCount() {
        return validCount;
    }
}

Spesifikasi Perbaikan

  1. Method normalize harus menghapus spasi awal/akhir dan menghasilkan kode dalam huruf kapital tanpa mengubah objek String masukan.
  2. Format, tahun, dan kategori yang salah merupakan kesalahan input pengguna dan harus ditangani menggunakan exception, bukan assertion.
  3. Setelah validasi input selesai, program boleh menggunakan assertion untuk memastikan invariant internal bahwa hasil parsing selalu memiliki tepat tiga komponen.
  4. validCount hanya bertambah apabila seluruh kode telah lolos validasi.
  5. Mahasiswa harus menggunakan .equals() atau bentuk pembandingan String lain yang benar dalam Java.

Soal 3. Gudang Peralatan Praktikum Generik

Bobot: 22%
Materi yang diuji: Java Generics, Java Generics Wildcard, Java Collection, Interface, Exception, dan Java Fundamentals.

Narasi Kasus

Laboratorium informatika mengelola peminjaman peralatan praktikum, seperti sensor, mikrokontroler, dan kabel penghubung. Semua peralatan memiliki kode unik dan nama, tetapi beberapa jenis peralatan memiliki informasi tambahan. Gudang perlu menyimpan data berdasarkan kode, menjaga urutan barang yang baru ditambahkan, serta memindahkan sejumlah peralatan yang tersedia ke daftar persiapan praktikum.

Karena kelas gudang akan digunakan untuk berbagai jenis peralatan, kelas tersebut harus dibuat generik. Selain itu, operasi pemindahan harus dapat membaca daftar yang berisi turunan dari Equipment dan menuliskannya ke collection tujuan yang dapat menerima Equipment.

Spesifikasi Sistem

  1. Seluruh peralatan mengimplementasikan interface Equipment yang memiliki method getCode() dan getName().
  2. Kelas EquipmentWarehouse<T extends Equipment> menyimpan:
    • pemetaan kode menuju objek peralatan agar pencarian berdasarkan kode efisien;
    • daftar urutan penambahan barang untuk kebutuhan pencetakan riwayat persediaan.
  3. Tidak boleh terdapat dua barang dengan kode yang sama dalam satu gudang.
  4. Operasi pengambilan berdasarkan kode yang tidak ditemukan harus melempar EquipmentNotFoundException.
  5. Disediakan method generik untuk menyalin seluruh barang dari sumber bertipe subtype Equipment ke collection tujuan yang dapat menerima objek Equipment.

Contoh Urutan Operasi

No. Aksi Kondisi Setelah Operasi

3 getByCode("S-01") Menghasilkan objek dengan kode S-01
4 removeByCode("S-02") Kode tersimpan: S-01
5 getByCode("S-99") Melempar EquipmentNotFoundException

Batasan Implementasi

  • Gunakan minimal satu Map dan satu List pada kelas gudang.
  • Jangan menggunakan raw type.
  • Method pemindahan harus menggunakan wildcard yang tepat; penggunaan wildcard harus memiliki alasan type-safety yang jelas.
  • Getter collection tidak boleh membuka struktur internal agar dapat dimodifikasi sembarangan oleh pemanggil.

Soal 4. Reservasi Slot Ruang Belajar Serentak

Bobot: 18%
Materi yang diuji: Java Multithreading, Java Collection, Exception, Assertion, dan Java Fundamentals.

Narasi Kasus

Perpustakaan kampus menyediakan ruang belajar kelompok yang dapat dipesan mahasiswa melalui beberapa terminal layanan sekaligus. Setiap ruang memiliki sejumlah slot yang terbatas untuk satu sesi waktu. Dua atau lebih mahasiswa dapat menekan tombol reservasi hampir bersamaan dari terminal berbeda.

Pada implementasi awal, setiap permintaan reservasi dijalankan dalam thread tersendiri. Namun, pengelola mendapati bahwa jumlah reservasi berhasil terkadang melampaui kapasitas ruang, atau jumlah slot tersisa menjadi negatif.

Implementasi Awal

// File: StudyRoom.java
import java.util.ArrayList;
import java.util.List;

public class StudyRoom {
    private final String roomCode;
    private int remainingSlots;
    private final List<String> confirmedStudents = new ArrayList<>();

    public StudyRoom(String roomCode, int capacity) {
        this.roomCode = roomCode;
        this.remainingSlots = capacity;
    }

    public void reserve(String studentId) {
        if (remainingSlots > 0) {
            try {
                Thread.sleep(20);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }

            confirmedStudents.add(studentId);
            remainingSlots--;
            System.out.println(studentId + " memperoleh slot.");
        } else {
            System.out.println(studentId + " gagal memperoleh slot.");
        }
    }

    public int getRemainingSlots() {
        return remainingSlots;
    }

    public List<String> getConfirmedStudents() {
        return confirmedStudents;
    }
}
// File: MainReservation.java
public class MainReservation {
    public static void main(String[] args) throws InterruptedException {
        StudyRoom room = new StudyRoom("R-201", 2);

        Thread t1 = new Thread(() -> room.reserve("13524001"));
        Thread t2 = new Thread(() -> room.reserve("13524002"));
        Thread t3 = new Thread(() -> room.reserve("13524003"));

        t1.start();
        t2.start();
        t3.start();

        t1.join();
        t2.join();
        t3.join();

        System.out.println("Sisa slot: " + room.getRemainingSlots());
        System.out.println("Peserta terkonfirmasi: "
                + room.getConfirmedStudents());
    }
}

Spesifikasi Perbaikan

  1. Satu slot hanya boleh diberikan kepada paling banyak satu mahasiswa.
  2. Jika seluruh slot telah terisi, method reservasi harus menyatakan kegagalan secara eksplisit melalui ReservationFullException.
  3. Daftar mahasiswa terkonfirmasi dan jumlah slot tersisa harus selalu konsisten.
  4. Program harus tetap menggunakan minimal tiga thread pemesanan.
  5. Setelah seluruh thread selesai, invariant internal bahwa jumlah slot tidak negatif boleh diperiksa menggunakan assertion.

Batasan Implementasi

  • Gunakan salah satu pendekatan berikut: method/blok synchronized, ReentrantLock, atau kombinasi operasi atomik dan collection thread-safe yang dapat Anda jelaskan kebenarannya.
  • Jangan menghilangkan multithreading dengan memanggil seluruh operasi reservasi secara serial dari main.
  • Method yang mengembalikan daftar mahasiswa harus tetap menjaga encapsulation.

Soal 5. Arsitektur Plugin Pemeriksa Berkas Pengumpulan

Bobot: 20%
Materi yang diuji: Java Reflection, Java Interface, Exception, Collection, Design Pattern, dan SOLID.

Narasi Kasus

Sebuah sistem pengumpulan tugas menerima berkas dari berbagai mata kuliah. Setiap mata kuliah dapat membutuhkan aturan pemeriksaan tambahan, misalnya pemeriksaan nama berkas, larangan ekstensi tertentu, atau pemeriksaan panjang deskripsi pengumpulan. Pengelola sistem tidak ingin menambahkan percabangan baru di kelas utama setiap kali aturan pemeriksaan baru dibuat.

Oleh karena itu, pemeriksa tambahan akan dibuat sebagai plugin. Nama kelas plugin disediakan melalui konfigurasi berupa sekumpulan String. Sistem harus memuat kelas tersebut saat runtime, memastikan bahwa kelas tersebut memenuhi kontrak plugin, membuat objeknya, lalu menjalankan validasi terhadap suatu objek pengumpulan.

Spesifikasi Sistem

  1. Sebuah pengumpulan direpresentasikan oleh kelas Submission yang memiliki studentId, fileName, dan description.
  2. Seluruh plugin pemeriksa harus mengimplementasikan interface SubmissionValidatorPlugin.
  3. Setiap plugin harus memiliki constructor tanpa parameter agar dapat dibuat melalui reflection.
  4. PluginLoader menerima nama kelas lengkap plugin sebagai String, memuat kelas dengan Class.forName, memeriksa kompatibilitas interface, dan membuat instance melalui constructor.
  5. ValidationEngine menyimpan beberapa plugin dan menjalankan seluruh plugin terhadap satu pengumpulan.
  6. Kegagalan pemuatan plugin harus dilaporkan melalui exception yang dirancang untuk aplikasi ini, tanpa menyebabkan program utama berhenti sebelum plugin valid lain dapat dicoba.

Batasan Implementasi

  • Gunakan reflection hanya untuk proses pemuatan dan pembuatan objek plugin.
  • Gunakan interface untuk menjalankan operasi validasi setelah objek plugin berhasil dibuat.
  • Gunakan collection untuk menyimpan plugin yang berhasil dimuat.
  • Tidak diperkenankan menggunakan rangkaian if-else yang membandingkan nama setiap kelas plugin untuk membuat instance.
  • Minimal terdapat dua implementasi plugin berbeda dalam skenario pengujian.
